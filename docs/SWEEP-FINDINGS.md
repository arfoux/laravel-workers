Tanggal: 2026-10-24

Tool: `build.mjs --strict` per app, vendor-lite dari content-addressed cache.
Apps disweep: laravel skeleton, monica, BookStack, invoiceninja
Apps gagal install vendor: crater (PHP 8.3 incompatible dep), snipe-it (classmap scan failure),

## RINGKASAN EXECUTIVE

Semua 4 apps yang berhasil vendor:ensure (laravel, monica, BookStack, invoiceninja)
**semuanya crash** karena satu root cause: app source files bundled dalam
`vendor/autoload_files.php` dengan path RELATIF ke vendor directory. Vendor-lite
hanya copy `vendor/`, bukan `app/` → autoload fail.

| App | Vendor-lite result | Build result | Root cause |
|-----|-------------------|--------------|------------|
| laravel/laravel (skeleton) | 42MB, hit cache | BUILD FAILED + crash | manifest check, autoload fail (app/Helpers) |
| monica (CRM) | 104MB | BUILD FAILED + crash | manifest check, autoload fail (app/Helpers/helpers.php) |
| BookStack | 133MB | BUILD FAILED + crash | manifest check, autoload fail (app/App/helpers.php) |
| invoiceninja | 756MB | BUILD FAILED + crash | manifest check, autoload fail (app/Helpers/TranslationHelper.php) |

**lw-real-test (working fixture)** tidak punya masalah ini karena:
1. app-nya tidak punya files-autoload entries pointing ke app/ source
2. Sudah punya manifest.json, .env, dan semua setup

## TEMUAN A — Build pipeline efficiency (P1, open since prior audit)

### A1. Boot cost per PHP invocation (CONFIRMED open)

`composer install` pada Laravel 13 skeleton: **379 s** (cold cache).
`build.mjs` spawns PHP 16× statically; untuk 50-route app = ~50 boot =
**~3-5 menit** dalam boot cost saja.

`compile-view.php` compile view yang sama 2× (routes/web.php:621 + 1278).
`.cache/laravel-workers/` ditulis tapi tidak dibaca ulang (tidak ada cache read).

**Proposed:** Satu long-lived PHP dispatcher yang boot Laravel sekali,
serve semua helpers via JSON-lines di stdin/stdout → N boots → 1 boot.

### A2. Redundant manifest check untuk apps tanpa frontend build

`autoSnapshot: false` di registry.json hanya skip snapshot. Manifest checktetap
berjalan dan BLOCK meskipun app memang tidak punya Vite/frontend build.

Ini menahan apps yang tidak punya `public/build/manifest.json` tapi juga tidak
membutuhkannya (API-only apps, apps dengan custom asset pipeline).

## TEMUAN B — vendor-lite: fundamental autoload architecture failure (P0)

### B0. Root cause (confirmed via direct test)

```php
// vendor/composer/autoload_files.php (generated by composer)
return [
    '...' => 'C:\vendor-lite-cache\HASH\vendor\composer/../../app/Helpers/helpers.php',
];
// Resolves to: C:\vendor-lite-cache\HASH\app\Helpers\helpers.php ← NOT PRESENT
```

Composer `--no-dev --optimize-autoloader` bundled "files" autoload entries
dengan path RELATIF ke vendor dir (`../../app/`). Ketika vendor-lite cache
dipindahkan ke machine lain, path ini invalid.

**Apps affected:** semua production Laravel app yang punya helper functions
di `app/Helpers/` atau `app/App/helpers.php` (Monica, BookStack, Invoiceninja,
dan mayoritas app nyata).

**lw-real-test works** karena app-nya tidak punya files-autoload pointing ke app/.

### B1. Graceful detection + message needed (P0)

vendor:ensure harus deteksi apps yang tidak bisa di-vendor-lite-kan SEBELUM
composer install gagal dengan generic error:

```
vendor:ensure: detected app-source autoload entries in composer.json:
  - "app/Helpers/helpers.php" (monica)
  - "app/App/helpers.php" (bookstack)
  - "app/Helpers/TranslationHelper.php" (invoiceninja)

These cannot be satisfied by the vendor-lite cache (which only contains vendor/).
For these apps: use full composer install:
  composer install --no-dev
```

### B2. Crater: PHP version incompatibility (P0)

**App:** Crater invoice
**Error:** `nette/schema v1.2.2 requires php >=7.1 <8.2 → your php 8.3.30`
**Fix:**
```
vendor:ensure: PHP version conflict detected.
  App's lock file requires PHP <8.2, you have 8.3.30.
  Fix: composer update --ignore-platform-reqs
  Or: use a PHP version compatible with the app
```

### B3. Snipe-IT: classmap generator failure (P1)

**App:** Snipe-IT
**Error:** `Could not scan for classes inside "database" which does not appear to be a file nor a folder`
**Root cause:** Snipe-IT punya `database` sebagai FILE, bukan folder. Composer classmap scanner gagal.
**Fix:** `composer install --no-dev --no-autoloader` + separate `composer dump-autoload -o`

### B4. Formbricks: bukan repo PHP (P0)

**App:** Formbricks (github.com/formbricks/formbricks)
**Error:** `ENOENT: no such file or directory, open 'composer.json'`
**Root cause:** Formbricks monorepo Node.js. composer.json tidak ada.
**Fix:**
```
vendor:ensure: no composer.json found — this does not appear to be a Laravel project.
  Formbricks is a Node.js monorepo and is not a target for laravel-workers.
```

## TEMUAN C — Build readiness output issues (P1)

### C1. Missing manifest → BUILD FAILED tanpa READINESS block (P1)

Semua 4 apps gagal di manifest check dengan pesan yang sama:
```
BUILD FAILED: no frontend manifest found — looked for public/build/manifest.json,
public/dist/manifest.json, public/mix-manifest.json — run the app's frontend build
(npm run build) first, or declare pages in registry.json "static"
EXIT 1
```

**Tidak ada READINESS block** — `fail()` exit(1) sebelum `renderReadiness()` dipanggil.
Operator tidak tahu apakah ini severity BLOCK atau tidak — hanya melihat BUILD FAILED.

**Root cause:** `fail()` push finding + `process.exit(1)`. `renderReadiness()` ada di akhir.
Early exit (manifest check, vendor check) melewati itu.

**Fix (minimal):**
1. `autoSnapshot: false` juga harus skip manifest check (karena tidak relevant
   untuk apps yang memang tidak punya frontend build)
2. Atau: `renderReadiness(findings)` dipanggil SEBELUM `process.exit(1)` — di dalam `fail()`

**Fix (recommended):**
`autoSnapshot: false` → skip BOTH snapshot AND manifest validation.
Operator yang disable autoSnapshot sudah bilang "saya handle sendiri page declarations".

### C2. Route dump crash: vendor-lite autoload failure (P0)

**Apps:** monica, BookStack, invoiceninja
**Error:** Exit 255, PHP Fatal Error — failed to open required vendor-lite/app/... path

Even when manifest check passed (invoiceninja), crash di `routes-dump.php` line 172.
Tidak ada READINESS sama sekali — crash stack trace di terminal.

**Fix:** vendor:ensure harus validasi autoload.php bisa di-load dengan app root
sebelum men-cachingkannya. Test: `php -r "require '$cache/vendor/autoload.php'"` —
jika gagal, jangan cache, print specific error.

## TEMUAN D — Messaging / specificity (P2)

### D1. "run the app's frontend build (npm run build) first" — tidak actionable

Semua 4 apps gagal manifest check dengan kalimat yang sama. Untuk production
apps, `npm run build` butuh APP_KEY, DB credentials, env setup. Tidak ada
indikasi bahwa app butuh env configuration.

**Proposed improvement:**
```
BUILD FAILED: no frontend manifest found — the build needs to know which pages exist.
  - For apps without a frontend build step: add to registry.json: {"autoSnapshot": false}
  - For apps with a frontend build: you need to configure the app first:
      cp .env.example .env
      php artisan key:generate
      npm install && npm run build
    Then re-run this build.
```

### D2. vendor:ensure success tanpa validation

vendor:ensure "success" (exit 0, prints cache path) BAHKAN ketika autoload.php
gagal di-load. Cache di-cetak tapi tidak bisa digunakan. Build baru gagal
kemudian dengan cryptic PHP crash.

**Fix:** Setelah `composer install`, vendor:ensure harus test:
```bash
php -r "require '$cache/vendor/autoload.php'; echo 'OK\n';"
```
Jika gagal: hapus cache, print error spesifik.

## TEMUAN E — Scope gap: production apps butuh setup lengkap

### E1. Production-grade apps tidak bisa langsung di-build

Even dengan vendor-lite, apps nyata butuh setup sebelum build.mjs bisa jalan:
1. `.env` file (APP_KEY, DB connection)
2. `npm install` + `npm run build` untuk frontend (bagi apps dengan Vite)
3. Database migration/schema
4. App harus bisa boot

Ini tidak realistis untuk "sweep banyak project" — setiap app butuh 10-30 menit
setup sebelum bisa di-build.

**Scope implication:** tool ini target-nya apps yang SUDAH running. Fresh clone
dari repo production butuh setup yang signifikan.

## UPDATE — 2026-10-24 (sweep session: fixes landed, findings re-verified)

### Fixed this session (all verified via real builds)

1. **C1 FIXED — `fail()` now always renders the READINESS block.**
   Before: `if (findings.length) console.error(renderReadiness(...)); else ...` — early
   exits (manifest check, LW_CONFIG/LW_PORTS_DIR) with empty findings → `renderReadiness([])`
   → verdict `RUNS ON THE EDGE` (misleading green) or nothing.
   After: unconditional `console.error(renderReadiness(findings, { dist: relPath(distFinal) }))`.
   Verified: bookstack/monica/invoiceninja route-crash builds now print
   `READINESS: DOES NOT RUN` + the blocking finding.

2. **C2 FIXED — route dump crash now emits a BLOCK finding (not just a crash).**
   Before: `execFileSync(PHP, routes-dump)` unguarded → throw → raw stack, no READINESS.
   After: try/catch → `note({severity: BLOCK, area: 'route', cause: 'the app failed to boot during route export', ...})` → `fail(...)`.
   Verified (bookstack, monica, invoiceninja): `READINESS: DOES NOT RUN` + cause names the boot failure.

3. **NEW — error-view compile failures now emit a BLOCK finding (was uncaught crash).**
   Before: `execFileSync(compile-view) + readFileSync(dumpPath)` unguarded → ENOENT crash, raw stack, no READINESS.
   After: try/catch around compile+parse → note BLOCK (`error view ${code} failed to compile`) → fail.
   Verified (laravel): `BUILD FAILED: compile-view failed for 401: ENOENT ... .cache/laravel-workers/errors.401.compiled.json` → `READINESS: DOES NOT RUN`.

4. **FIXED — config-dump catch now adds the BLOCK note before fail().**
   Before: `catch (e) { fail('config dump failed: ...') }` — no note → findings empty → verdict `RUNS ON THE EDGE` (green!) on a FAILED build. This is why invoiceninja's config-dump failure printed `RUNS ON THE EDGE`.
   After: catch adds `note({severity: BLOCK, area: 'config', cause: 'runtime config dump failed: ...'})` → fail.
   Verified (invoiceninja): now prints `BUILD FAILED: config dump failed: ...` → `READINESS: DOES NOT RUN` + finding.

5. **lw_boot_app() now auto-generates + injects APP_KEY** (fresh clones boot without manual `php artisan key:generate`).
   Before: `lw_boot_app()` only registered App\ + booted; missing APP_KEY → boot crash (fresh clone).
   After: `if (!putenv('APP_KEY')) { generate base64 key; set $_ENV/$_SERVER/putenv }` before autoload + boot.
   Verified: laravel skeleton (fresh clone, no .env) got PAST route export (2 routes) after this → proceeded to error-view compile.

6. **vendor-lite.mjs: dead PSR-4 injection block removed** (superseded by lw_boot_app's `addPsr4`).

### Fixed this session (follow-up): error-view write robustness + regression caught

1. **build.mjs**: tambahkan `mkdirSync(cacheDir, { recursive: true })` sebelum loop
   error-view menulis dump ke `<app>/.cache/laravel-workers/errors.<code>.compiled.json`.

2. **tools/compile-view.php**: `file_put_contents` kini diverifikasi — kalau gagal,
   `fwrite(STDERR, ...)` + `exit(1)`, supaya kegagalan tulis tidak diam-diam lalu
   crash di `readFileSync` (yang bikin build kehilangan READINESS sama sekali).

3. **Regression terdeteksi**: edit via Python menulis file dengan line-ending CRLF
   → regex test (`/^\s*if \(prepared\.length\) \{$/`) gagal → test
   `compiler/tests/source-syntax.test.mjs` ("every generated module the worker
   imports is always emitted") gagal. Diperbaiki dengan menulis ulang ke LF.
